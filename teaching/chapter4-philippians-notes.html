用 AI 编程助手创作圣经游戏

以腓立比书《以巴弗提的旅程》为例，学习怎样用 Claude Code 或 Codex，把一卷书信做成一个可以在手机上玩、可以带进家庭和小组的圣经游戏。

范例游戏　腓立比书《以巴弗提的旅程》 建议课时　两堂，每堂约 90 分钟 先修　会用电脑和手机浏览器即可，不需要会写程序

一、学习目标与课前准备

学完这一章，你能够：

  1. 说明「游戏机制本身就在传达神学」的意思，并举出腓立比书游戏的三个例子。
  2. 用「神学主导、AI 实作」的方式，和 Claude Code 或 Codex 一起完成一个圣经游戏的构思、查证、实作、修订。
  3. 为自己的项目写一份「项目记忆」文件（CLAUDE.md 或 AGENTS.md），让 AI 每次都遵守你定下的神学原则。
  4. 辨认与 AI 协作时常见的陷阱：顺从不提醒、引用未查证、把神学判断交给 AI。

课前准备

  • 一个 GitHub 帐户，开一个空的仓库（例如 bible-games）。
  • Claude Code（网页版、桌面版或命令行皆可）或 OpenAI Codex 其中一种。
  • 先玩一次范例游戏：以巴弗提的旅程（作者需开放分享后，学生才打得开）。
  • 选好你想做的一卷书信，读完全卷至少一次。

二、为什么用游戏教圣经

讲道和查经用的是语言，游戏还多了一样东西：动作。玩家用手按住、放开、躲开、抓住，这些动作本身就会教人。游戏设计里有一个说法叫「程序修辞」：规则和机制会说话，而且常常比文字说得更深。

举例：腓立比书游戏里，「凭自己反击」病菌，病菌反而分裂成两个；「用力挣脱」资历的蛛网，反而缠得更紧。玩家不必读一句解释，手已经学会了「靠自己是不行的」。

本章的核心问题

不是「怎样把经文放进游戏」，而是「哪一个动作，能让玩家亲身经历这段经文的真理」。

三、认识工具：Claude Code 与 Codex

两者都是「AI 编程助手」：你用平常的话告诉它要做什么，它会读你的项目、写程序、执行测试、存进版本库。你不必会写程序，但你要会说清楚想要什么，并判断它做得对不对。

Claude CodeAnthropic 出品。可在网页（claude.ai/code）、桌面应用或命令行使用。项目根目录的 CLAUDE.md 是它的「项目记忆」，每次对话开始都会读。
CodexOpenAI 出品，同类的 AI 编程助手。它读取的项目说明文件是 AGENTS.md，用法和 CLAUDE.md 相同。

本章的流程两种工具都适用。下文的提示语以 Claude Code 为例；换成 Codex 时，把 CLAUDE.md 改成 AGENTS.md 即可。

为什么选「单一 HTML 文件」

  • 手机、电脑打开就能玩，不用安装，适合家庭和小组。
  • 一个文件就是全部，容易保存、分享、放上 GitHub Pages。
  • AI 编程助手处理这类项目最稳定，修改也容易检查。

四、范例：《以巴弗提的旅程》

一句话：跟着以巴弗提从腓立比走到罗马，再带着保罗的信回家。同一条路，同样的病菌，不同的是走路的人。

他为做基督的工夫，几乎至死，不顾性命，要补足你们供给我的不及之处。腓立比书 2:30
段落经文剧情与玩法
序幕 · 去程4:2；2:25-30背着教会不同心、外面敌对、忧虑三块石头上路。结党、嫉妒、纷争、怨言化成病菌，一波一波躲不过，只能争战，每打一仗也沾染一点。圣灵的供应以油和水迎面送来。最后几乎病死在罗马城外，「然而神怜恤他」（2:27）。
第一章 · 罗马1:3-30五个处境的选择。「顺着圣灵」的路一开始是模糊的，要先长按「等候」被光照才看得见。保罗面对出于嫉妒的传道人说：「这有何妨。」
第二章 · 代赎的阶梯2:5-13先选角色（孩子、父母、照顾者、长辈、一家人）。基督的光一级一级降到家里九个处境；长按「让祂降下来」20 秒，浮现经文、问题、圣灵在里面的祷告、代赎的结果。
第三章 · 标竿3:3-14资历像蛛网一排排缠上来，越挣越紧。抓住从上面来的 4:8 之光才松开；最深的「自以为义」只有等候基督来得着你（3:12）。
第四章 · 回程4:2-9平安守着他，病菌会打薄它，抓住 4:8 之光就加厚（4:9）。进城前有 40 秒的「思念」练习，再带着平安去见两位姊妹。
终章 · 未完1:3-6读信读到两姊妹的名字时停住。长按「等候」，生命树九层根扎下（基督已成），果子还在长（圣灵还在做），以 1:6 作结。

游戏共 27 段，目录全部开放，每段标出要读的经文；每段开始自动存档，可以「先玩一段，再读经」。

五、设计哲学

1. 两条神学控制线

每一个设计决定，都要回到这两条线检查：

代赎基督的行动是为我们、代替我们的（林后 8:9）。经文里基督的步伐不是给我们模仿的榜样，是祂降到我们的处境，带来代赎的结果。
耶稣基督的灵在我们里面祷告玩家能走下去，是因为祂的灵在里面祷告（腓 1:19；罗 8:26；加 4:6）。游戏里的「等候」按钮就是这条线。

2. 机制就是神学

游戏机制传达的真理
「等候」按钮对圣灵敞开；去程锁着，到「神怜恤他」才打开
反击、挣脱、我自己来每次都适得其反：画面剧烈摇晃、缠得更紧
争战躲不过，每次都沾染以巴弗提是「一同当兵」的（2:25），代价是真实的
油和水，与果子分开路上的供应是补给，果子是圣灵结出来的
平安会变薄，领受就更新美德只靠自己持守会腐败；赐平安的神与领受的人同在（4:8-9）
自以为义只有基督能松开不是我们抓住祂，是祂得着我们（3:12）
根全部亮，果子还在长基督已成，我们未成，直到基督的日子（1:6）

3. 其他原则

  • 不读成道德主义：「向着标竿直跑」不是靠意志力的赛跑，每一处「努力」都引回代赎和圣灵的大能。
  • 忠于经文，坦白交代判断：例如 1:15-17 嫉妒传道发生在罗马不在腓立比；「病菌」是寓意，经文没交代病因；圣经没记载两姊妹是否和好，所以结局留白。
  • 为真实的用家设计：对象是中国大陆的多代家庭；处境取材于家庭研究（三代动力、夹心照顾、双职与单亲、代代相传的打骂）。
  • 牧养护栏：顺服不等于忍受家暴；和好不必勉强、不必马上；碰到暴力题材附上求助资讯。
  • 不计分，不比快：结算只有「旅程记录」和去程、回程的对照。

六、七步工作流程

下面每一步都附上范例项目中真实用过的提示语（略作整理）。分工原则只有一句：作者掌握神学与牧养判断，AI 负责查考、设计建议与实作。

  1. 立项：先要构思，不要程序

    第一句话就要求 AI 先说构思。这样你有机会在它写任何程序之前，修正方向。

    你帮我把腓立比书做成圣经游戏，你先说说你的构思。

    AI 第一版提出「喜乐值」、四章四关。作者接着补上自己的神学构想：用以巴弗提的旅程、教会纷争的重担、病到几乎要死、圣灵的果子、向下扎根。AI 据此重写构思。

  2. 研经查证：让 AI 查，自己判断

    遇到经文解释的关键点，请 AI 查主流注释并附来源，再由作者决定。

    你先帮我查考当代最好的注释书怎样看保罗说「有人因嫉妒纷争传基督」，这件事发生的地点是在罗马，还是在保罗所关心的腓立比教会？先查清楚。

    结果：主流注释认为在罗马；但 1:17 和 2:3 的「结党」（ἐριθεία）互相呼应，同样的病也在腓立比发作。作者据此决定：去程背着腓立比的结党，到了罗马才看见同一个病菌。

  3. 写下项目记忆

    把定下来的神学原则写进 CLAUDE.md（Codex 用 AGENTS.md）。以后每次开新对话，AI 都会先读它。

    这些美德唯有靠基督的义去成就，更具体就是耶稣基督的圣灵，背后是对三位一体真神的顺从。你要把这个观点记在记忆中。

    范例项目的 CLAUDE.md 包括：对象、工作方式、两条神学控制线、其他原则、牧养护栏、本卷的研经判断。见作业部分的范本。

  4. 实作第一版

    构思确认后才说「开始做」。要求单一 HTML、手机可玩、简体中文和合本。AI 会写程序、自己测试，并给你一个试玩链接。

  5. 试玩，然后具体地说

    亲自玩，把感受说得具体：哪一段、哪一句、太短还是太长、像不像经文的意思。

    第二章往上抓点一下的时候，震动要更高级别、剧烈的晃动；向下走按住不放的时间要更长，起码二十秒，让人真的能够消化、敏感这种在圣灵里向下走的经验。

  6. 请 AI 评估，而不只是照做

    重大改动前，要求 AI 以专业角度评估：好在哪里、风险在哪里、市面上的好游戏怎么做。

    我再提醒你作为顶级的游戏设计师，对我的建议作出评估，作回应。

    例：作者提议把「等候」改名为「向下扎根」。AI 评估后建议全程保留「等候」，以免混淆两条控制线，只在结局揭示「你一路的等候，原来就是向下扎根」。作者采纳。

  7. 版本、定稿与发布

    • 每一卷书一个开发分支；修订阶段只推送分支，作者说「定稿」才合并到 main。
    • 公开发布可用 GitHub Pages、Netlify Drop，或直接分享试玩链接。
    • 对话太长时，开新对话做下一卷；靠 CLAUDE.md 延续原则。

个案作者的回馈改动学到的功课

八、提示语范本

把方括号里的内容换成你的书卷和想法。每一张卡片都可以直接复制。

我想把[书卷]做成一个圣经游戏，对象是[对象]。请先读完 CLAUDE.md，然后告诉我你的构思：故事框架、每一章的玩法、贯穿全局的机制。先不要写程序。
请查考主流注释（附来源），说明[经文]的[问题]。分开列出：学者的共识、仍有争论的地方、你不确定的地方。
这段经文的核心真理是[真理]。请提出三个不同的游戏机制，让玩家用动作经历这个真理，并说明每个机制可能被误读成什么。
请以顶级游戏设计师的角度评估我的建议：好在哪里、有什么神学或设计上的风险、市面上好的游戏怎么处理类似的问题。先评估，等我决定再动手。
照我们确认的方案做。要求：单一 HTML 文件，手机可玩，简体中文，和合本经文。做完请实际测试，如实告诉我哪些测过、哪些没测过。
我试玩了[段落]，问题是[具体描述]。请先说你的理解，再修改。
请把这个原则写进 CLAUDE.md，让以后每一卷都遵守：[原则]。

九、与 AI 协作的守则

神学判断永远是你的

AI 可以查注释、提方案、指出风险，但哪一个解释、哪一个牧养取向，由作者决定。范例中每一个神学转向（代赎的阶梯、反道德主义、两条控制线）都是作者提出的。

要求它提醒你，而不只是顺从

AI 倾向照你说的做。养成习惯，在重大改动前问「请评估」。范例中 AI 曾提醒：语音输入把「腓立比书」说成「以弗所书」；「斗拳不是打空气」出自哥林多前书 9:26，不在腓立比书。

引用要查证

请 AI 附来源。不确定的资料（例如求助热线号码），要在上线前再核实。

先说理解，再动手

口语描述常有歧义。请 AI 先复述你的意思，确认无误再改，可以省下很多来回。

小步修改，每步试玩

一次只改一个部分，改完立刻试玩。AI 应如实报告测试结果，包括没测到的地方。

游戏文字与设计讨论分开

讨论时可以用「化疗」「共生」这类比喻帮助思考，但游戏里只呈现经文和故事本身。

牧养护栏不能省

碰到家暴、羞辱、哀伤等题材，要写明：顺服不等于忍受暴力，和好不必勉强，并附上可信的求助资讯。

十、课堂练习与作业

课堂练习（30 分钟，三至四人一组）

  1. 选一段经文（建议：腓利门书全卷，或帖撒罗尼迦前书 4:13-18）。
  2. 写出这段经文的一句核心真理。
  3. 设计一个「动作」，让玩家用手经历这个真理；再写出这个动作可能被误读成什么。
  4. 用两条神学控制线检查：这个设计里，基督做了什么？圣灵在哪里？

作业：一卷书信的游戏原型

  • 为你选的书卷写一份 CLAUDE.md（或 AGENTS.md），至少包括：对象、两条神学控制线在本卷的样子、三条研经判断、牧养护栏。
  • 和 AI 一起完成一个可玩的原型，至少一章，单一 HTML。
  • 附一份「机制即神学」对照表，至少三项。
  • 附一页修订记录：你给过哪些回馈、AI 怎样回应、你最后怎样决定。

评分重点

项目看什么比重
经文忠实解释有根据，判断交代清楚，不替圣经补写30%
机制即神学动作本身就在传达真理，没有落入道德主义30%
用家与牧养贴近真实对象的处境，护栏到位20%
协作过程修订记录显示作者主导神学、善用 AI 评估20%

CLAUDE.md 范本（节录自范例项目）

## 对象 - 多代家庭：孩子、父母、照顾年老父母的中间一代、长辈。开场先选角色。 ## 工作方式 - 游戏文字用简体中文，经文用和合本。 - 修订阶段只推送开发分支；作者说「定稿」才合并。 - 游戏里不用现代术语解释属灵逻辑。 ## 两条神学控制线 1. 代赎：基督为我们、代替我们（林后 8:9）。写法是「因为基督……，所以我们……」。 2. 耶稣基督的灵在我们里面祷告（腓 1:19；罗 8:26；加 4:6）。 ## 牧养护栏 - 顺服是对天父，不是对伤害你的人。 - 和好是圣灵一步一步的工作，不必勉强、不必马上。

十一、讨论题

  1. 「机制本身就在讲神学」：你玩范例游戏时，哪一个动作让你最有体会？为什么？
  2. 第二章从「我们学着向下走」改成「基督为我们降下来」。这个改动在神学上和玩家感受上，各带来什么不同？
  3. 游戏怎样才不会变成「靠努力过关」的道德主义？请举一个你自己的设计为例。
  4. 和 AI 协作时，哪些决定应该交给它，哪些一定要自己做？
  5. 你的教会或家庭，最适合在什么场合使用这样的游戏？要怎样配合读经和分享？
